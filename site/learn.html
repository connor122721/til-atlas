Learn the methods

A path through the data behind this site, from pulling a public API to fitting a model of clonal dynamics. Each section ends with an exercise that changes something you can see on the site.

Where the data come from

The Datasets page lists every public cohort wired into this site — TIL-ACT single-cell (Lausanne, cervical), checkpoint single-cell (Sade-Feldman, Pozniak), and spatial (Xenium melanoma, melanoma IMC, cSCC and HNSCC CosMx) — with accessions, access status and the script that loads each one. A weekly GEO watch adds candidates as they're released.

1 · Pulling data from an API

ClinicalTrials.gov's v2 API is one endpoint, /api/v2/studies, steered by query parameters. The scraper in scraper/fetch_trials.py does four things worth copying for any data source:

  • Cursor pagination. Each response includes nextPageToken; pass it back as pageToken until it's absent. Never assume page numbers.
  • Flatten early. The raw JSON nests everything under protocolSection.<module>. normalize() pulls out ~20 fields so the website never touches the raw shape.
  • Derive, don't hand-curate. Indication and design tags come from regexes in tags.json, so re-tagging 500 trials is one edit.
  • Keep history as diffs. Each run compares against last week's snapshot and appends to changelog.json; git itself is the archive.
python scraper/fetch_trials.py --dry-run          # fetch + count by status, write nothing
python -m unittest discover -s scraper/tests       # offline tests against a synthetic fixture

2 · Scoring cell states

Krishna's two states are defined by surface markers (CD39, CD69) and backed by transcriptional signatures. On scRNA-seq you score each cell for a gene set. Two common choices:

  • UCell ranks genes within each cell and computes a Mann–Whitney U statistic for the signature genes versus the rest, scaled to 0–1. It doesn't depend on the other cells in the dataset, so scores are comparable across batches.
  • Seurat AddModuleScore subtracts the mean of expression-matched control genes. It's sensitive to dataset composition, so re-scoring a subset changes the values.

Dropout makes single markers unreliable: ENTPD1 (CD39) and TCF7 are often zero in cells that express the protein. That's why signatures, or CITE-seq antibodies for CD39/CD69 when you have them, beat single genes.

Exercise. Replace the starter panels in analysis/signatures/ with the DN/DP genes from the Krishna supplement, re-run 01_score_signatures.R, and check whether the stem-like share still separates responders in the lab's strip plot.

3 · Counting clones

A clonotype is usually defined by the CDR3β amino-acid sequence (plus V gene), or by the paired α/β chains when you have single-cell data. The metrics used in ACT papers:

frequency       f_i = reads_i / total reads in the sample
clonality       1 − H / ln(N),   H = −Σ f_i ln f_i,  N = number of clones   (0 = even, 1 = one clone)
persistence     share of a post-infusion blood repertoire made of clones present in the product
Morisita–Horn   C = 2 Σ x_i y_i / ((Σx_i² / X² + Σy_i² / Y²) · X · Y)   overlap of two samples, 0–1

Sampling depth bounds everything: a clone at frequency f appears in n reads with probability 1 − (1 − f)ⁿ. At 20,000 reads a clone at 10⁻⁵ is caught about 18% of the time, so “not detected” is not “gone”. The simulator's blood table shows this directly: compare persistence (what you'd sequence) with true infused share.

Exercise. In the simulator, pick the stem-poor preset and watch the number of detected clones fall faster than the true infused share. Then compute Morisita–Horn between product and day-30 blood in 02_clonotypes.R for each Barras/Chiffelle patient.

4 · Spatial data

Spatial platforms differ mainly in what one measurement unit is:

  • GeoMx (used in the Moffitt study): whole transcriptome per hand-picked region of interest. Analyze like bulk RNA-seq with a region-type covariate (tumor, immune, TLS).
  • Visium: spots of ~55 µm holding several cells; deconvolve to cell-type proportions (e.g. cell2location, RCTD).
  • Xenium / CosMx / CODEX / multiplex IF: single cells with coordinates. Here you can ask neighborhood questions: is CD8 within 20 µm of CD11c⁺ myeloid more often than chance (permutation of labels)?

For a static site, ship summaries rather than images: per-sample neighborhood enrichment, cell-type densities by region, and a small cell table for one showcase section. Full images belong in OME-Zarr on object storage, viewed with Vitessce.

Exercise. Run the Xenium melanoma recipe in analysis/spatial/README.md, then re-export with --radius 15 and --radius 50. Which CD8⁺ contacts on the Spatial tab survive the change? Then do the same for the IMC anti-PD-1 cohort and compare CD8–myeloid z-scores between responders and non-responders.

5 · Fitting the model

The simulator's parameters are set by hand. To fit them to real trajectories, the simplest honest method is approximate Bayesian computation:

  1. Pick summary statistics you can compute both from data and from simulations: persistence at days 7/30/90, top-clone share, number of detected clones.
  2. Draw parameters from priors (say, log-uniform for each rate), simulate, and compute the same statistics.
  3. Keep draws whose statistics land within a tolerance of the observed ones. The kept parameters approximate the posterior.

Because site/assets/sim-model.js runs in Node unchanged (require("./sim-model.js").simulate({...})), you can run 10⁵ simulations on the cluster without touching the website code.
